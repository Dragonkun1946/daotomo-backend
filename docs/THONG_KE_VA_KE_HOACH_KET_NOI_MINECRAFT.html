Tổng Quan Hiện Trạng Hệ Thống & Kết Quả Kiểm Toán (Audit)

ℹ️
Nguyên tắc thực thi: Toàn bộ quá trình khảo sát được thực hiện ở chế độ CHỈ ĐỌC (Read-Only). Tuyệt đối không can thiệp, không tạo/sửa/xóa file trong source code, không chạy migration và không khởi tạo dịch vụ thật.

1.1. Khảo Sát Source A — Website Đảo Tò Mò (daotomo-backend)

Hệ thống website thương mại điện tử Đảo Tò Mò được xây dựng bằng framework Laravel 11.31 (PHP 8.2+) theo mô hình Clean Architecture:

  • Kiến trúc phân tầng: Phân chia rõ ràng giữa Controllers (Api/Admin), Requests (Form Validation), Services (SepayService, OrderService, PasswordResetService, SkinService, DiscordOAuthService), Models và API Resources.
  • Cơ sở dữ liệu (Database): Gồm 6 bảng cốt lõi (users, products, orders, order_items, payment_transactions, checkins). Trong DatabaseSeeder đã định nghĩa 12 sản phẩm thuộc 3 danh mục (Xu Game, Gói Bậc Rank, Chìa Khóa Rương).
  • Xác thực (Auth): Laravel Sanctum (Token-based Auth), mã hóa mật khẩu Bcrypt, tích hợp đăng nhập mạng xã hội Discord OAuth2.
  • Cổng thanh toán SePay VietQR: Tự động sinh mã VietQR NAPAS 24/7 theo đơn hàng, kiểm tra chữ ký HMAC-SHA256, kiểm tra drift thời gian < 300s, cơ chế chống trùng đơn bằng idempotency_key và tự động phục hồi giao dịch.
  • Hệ thống Email đa tầng: Ưu tiên gửi qua Resend / Brevo HTTPS API Cổng 443 giải quyết triệt để lỗi tường lửa chặn SMTP khi host trên Render.
  • Frontend & 3D WebGL: Design System 2.0 "Neo-Mythic Island", nhúng trực tiếp Three.js WebGL (skinview3d.bundle.js) để xoay 360 độ skin nhân vật và tự động bóc tách avatar khuôn mặt qua thư viện PHP GD.

1.2. Khảo Sát Source B — Máy Chủ Minecraft (Paper 1.21.11 Earth Survival)

Máy chủ Minecraft sử dụng bản cài đặt Premium Earth Survival Setup V3.7.6 (NitroSetups):

  • Server Core & Engine: Paper 1.21.11 build 132 (paper-1.21.11-132.jar), vận hành trên môi trường Java 21 LTS (-Xms4G -Xmx8G).
  • Thông số mạng & Định danh: server-port=25565, online-mode=true (Xác thực tài khoản bản quyền Mojang, người chơi có UUID v4 vĩnh viễn), enable-rcon=false (Cổng RCON bị tắt mặc định vì lý do an ninh).
  • Hệ thống Phân quyền (Permissions): LuckPerms 5.4 (H2 Database) với cây tiến trình rank 5 bậc: knight → lord → paladin → duke → king.
  • Hệ thống Tiền tệ (Economy): Sử dụng kép giữa Vault + EssentialsX (tiền mặt lưu thông $) và CoinsEngine 2.6 (đồng xu đặc quyền coins ⛃ dùng trong /coinshop, lưu tại SQLite data.db).
  • Hệ thống Phần thưởng (Rewards): ExcellentCrates (5 hòm rương thần), CrazyVouchers (11 phiếu thưởng vật phẩm/quyền lợi), DeluxeMenus (/rewards điểm danh).
  • Hệ thống Bổ trợ: factoriesitems.sk (Nguyên liệu công nghiệp: Crude Oil, Gasoline, Hydrogen, Uranium), Minepacks (ba lô mở rộng), DeluxeTags (150+ danh hiệu quốc gia), GeyserMC & Floodgate (hỗ trợ người chơi Bedrock di động).

Kế Hoạch Kỹ Thuật Chi Tiết 5 Module Tích Hợp Độc Lập

3.1. MODULE A — Xác Thực & Liên Kết Tài Khoản (Account Linking)

⚠️
Rủi ro hiện tại: Giao diện web hiện tại chỉ cho người dùng tự gõ username text (qua regex). Bất kỳ ai cũng có thể nhập tên tài khoản của người khác hoặc các streamer để nhận đồ, gây gian lận nghiêm trọng. Ngoài ra nếu người chơi đổi tên (Mojang cho phép đổi tên sau 30 ngày), toàn bộ liên kết sẽ bị đứt nếu không lưu UUID.

Giải pháp chuẩn hóa: Cơ chế Bắt tay Mã PIN Xác thực 6 Ký tự (In-Game OTP PIN Handshake)

1

Người chơi vào Server Game gõ lệnh /link

Plugin Bridge tiếp nhận, sinh mã PIN ngẫu nhiên 6 ký tự (VD: DTM-8492), lưu vào bộ nhớ đệm (Cache) gắn liền với UUID và Username trong 10 phút.

2

Nhập mã PIN trên Website Đảo Tò Mò

Người chơi đăng nhập tài khoản Web, vào mục "Liên kết Game", nhập mã DTM-8492. Web gửi request lên backend.

3

Xác thực và ghi nhận quyền sở hữu

Backend kiểm tra mã PIN qua Bridge. Sau khi hợp lệ, lưu minecraft_uuid và minecraft_username vào bảng users. Khóa liên kết 1-1 (1 tài khoản web chỉ liên kết 1 UUID Minecraft).

4

Bắn thông báo chúc mừng & Phát quà tân thủ

Server Minecraft gửi tin nhắn chat riêng: "Tài khoản của bạn đã liên kết thành công với website daotomo.site!" và tự động tặng 1 Key Vote Crate.

3.2. MODULE B — Hệ Thống Điểm Danh Game & Web (Daily Check-in)

Hiện nay máy chủ Minecraft dùng DeluxeMenus /rewards (lưu cooldown qua nhóm tạm LuckPerms), trong khi Website có bảng checkins lưu lịch sử điểm danh nhận xu web.

  • Múi giờ & Chu kỳ reset: Thống nhất múi giờ tiêu chuẩn Asia/Ho_Chi_Minh (UTC+7). Thời điểm reset là 00:00:00 mỗi ngày.
  • Cơ chế đồng bộ 2 chiều:
    - Khi điểm danh trên Web: Hệ thống ghi nhận chuỗi ngày (streak), cộng Xu Web, đồng thời tạo một bản ghi giao quà game (VD: 100 Xu hoặc 1 Crate Key) vào hàng đợi.
    - Khi điểm danh trong game: Plugin Bridge gửi tín hiệu sync về Web để hiển thị chuỗi ngày trên giao diện người dùng.
  • Chống gian lận điểm danh lặp: Ràng buộc Unique Constraint UNIQUE(user_id, checkin_date) ở tầng Database đảm bảo một ngày chỉ được nhận thưởng một lần duy nhất kể cả khi gửi đồng thời nhiều request.

3.3. MODULE C — Hệ Thống Tiền Tệ & Xu Trong Game (Currency System)

🛑
Quy tắc bất biến: Tiền nạp SePay (VND), Xu Website (Web Coins) và Xu Game (CoinsEngine ⛃) là 3 loại tài sản có bản chất hoàn toàn khác nhau. Tuyệt đối không cho phép đổi ngược từ Xu Game thành tiền thật (VND) để tránh rủi ro pháp lý.
  • Nguồn dữ liệu gốc (Single Source of Truth): Số dư Xu trong game thuộc quyền quản lý tối cao của CoinsEngine (lưu tại SQLite plugins/CoinsEngine/data.db). Website KHÔNG lưu số dư game trực tiếp vào bảng users mà chỉ đóng vai trò ủy quyền thực thi (Granting Authority).
  • Cơ chế cộng xu an toàn: Mọi thao tác cộng xu từ Web (do nạp tiền hoặc thưởng nhiệm vụ) đều phát sinh qua lệnh coins give {player} {amount} đính kèm idempotency_key (Mã đơn hàng) để ngăn chặn việc cộng xu 2 lần khi mạng chập chờn.

3.4. MODULE D — Luồng Thanh Toán SePay & Giao Vật Phẩm Tự Động

Quy trình xử lý một đơn hàng từ lúc quét mã VietQR đến khi nhận được item trong server game:

1

Khách hàng tạo đơn & Quét mã SePay VietQR 24/7

Hệ thống bắt buộc khách đã liên kết tài khoản Minecraft (để có minecraft_uuid). Đơn hàng sinh mã nội dung chuyển khoản chuẩn (VD: DTM1024).

2

SePay Webhook xác nhận thanh toán hợp lệ

Hệ thống xác thực chữ ký HMAC-SHA256, chuyển trạng thái payment_status = 'paid', order_status = 'processing'.

3

Đẩy lệnh vào Bảng Hàng Đợi Giao Game (game_delivery_queues)

Hệ thống tự động phân tách các items trong đơn hàng thành danh sách lệnh console tương ứng (theo Bảng 2.3), gán trạng thái pending.

4

Plugin Bridge trên Paper kéo lệnh và thực thi an toàn

Định kỳ 3 giây, plugin gửi request nội bộ kéo các lệnh đang chờ, chạy trên Bukkit Main Thread.

5

Xử lý Người Chơi Offline & Rương Đầy (Edge Cases)

Xu (Coins) & Bậc Rank (LuckPerms): Hoạt động offline 100% qua UUID! Giao ngay lập tức.
Vật phẩm hòm rương / Physical Item: Nếu người chơi đang offline hoặc đầy kho đồ, plugin chuyển trạng thái thành waiting_online. Khi người chơi đăng nhập, plugin tự động trao đồ vào hòm thư ảo (Virtual Mailbox), tránh rơi rớt đồ ra đất.

6

Báo cáo Hoàn Tất & Gửi Biên Lai

Plugin gọi API xác nhận hoàn tất. Đơn hàng chuyển sang order_status = 'completed', gửi email hóa đơn cho người mua.

3.5. MODULE E — Kiến Trúc Giao Tiếp Khuyên Dùng (DaoTomoBridge Plugin)

So sánh các phương án kiến trúc kết nối giữa Website và Minecraft Server:

Phương Án Ưu Điểm Nhược Điểm / Rủi Ro Khuyến Nghị
1. RCON (Port 25575) Có sẵn trong Minecraft server mặc định Bảo mật cực kém (mật khẩu clear-text), dễ bị Brute-force, server hiện đang tắt enable-rcon=false. Tuyệt đối không dùng
2. Mở Port Webhook trên Server Game Phản hồi tức thì (Real-time) Bắt buộc phải mở Port Forwarding / NAT trên Router máy chủ, nguy cơ bị DDoS làm sập game. Rủi ro cao
3. Dùng chung Database MySQL Không cần viết code mạng Gây xung đột lock dữ liệu, không bắn được event/thông báo trong game theo thời gian thực. Không linh hoạt
4. Outbound Polling Bridge (DaoTomoBridge.jar) KHÔNG CẦN MỞ BẤT KỲ CỔNG NÀO TRÊN SERVER MINECRAFT, xuyên qua mọi tường lửa/NAT, bảo mật Bearer Token, chạy lệnh an toàn trên Bukkit Main Thread. Có độ trễ nhỏ từ 1 - 3 giây (hoàn toàn chấp nhận được trong trải nghiệm game). KHUYÊN DÙNG SỐ 1

Thiết Kế Cơ Sở Dữ Liệu & Bản Di Trú (SQL Schema) Mới

Để triển khai kế hoạch trên mà không làm ảnh hưởng đến cấu trúc hiện có của website, hệ thống chỉ cần bổ sung 1 bảng mới game_delivery_queues và thêm các cột định danh vào 2 bảng users và orders:

database/migrations/2026_10_29_add_minecraft_integration_tables.sql 
-- 1. Bổ sung trường định danh Minecraft vào bảng users
ALTER TABLE `users` 
ADD COLUMN `minecraft_uuid` VARCHAR(36) NULL UNIQUE AFTER `email`,
ADD COLUMN `minecraft_username` VARCHAR(32) NULL AFTER `minecraft_uuid`,
ADD COLUMN `minecraft_linked_at` TIMESTAMP NULL AFTER `minecraft_username`;

-- 2. Bổ sung trường theo dõi giao hàng vào bảng orders
ALTER TABLE `orders`
ADD COLUMN `minecraft_uuid` VARCHAR(36) NULL AFTER `user_id`,
ADD COLUMN `delivery_status` ENUM('pending', 'delivering', 'completed', 'failed') DEFAULT 'pending' AFTER `order_status`,
ADD COLUMN `delivered_at` TIMESTAMP NULL AFTER `delivery_status`;

-- 3. Tạo bảng hàng đợi giao vật phẩm trong game (Idempotent Delivery Queue)
CREATE TABLE `game_delivery_queues` (
    `id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `order_id` BIGINT UNSIGNED NOT NULL,
    `order_item_id` BIGINT UNSIGNED NULL,
    `minecraft_uuid` VARCHAR(36) NOT NULL,
    `minecraft_username` VARCHAR(32) NOT NULL,
    `reward_type` ENUM('coin', 'rank', 'crate_key', 'voucher', 'custom_cmd') NOT NULL,
    `command_payload` VARCHAR(255) NOT NULL,
    `idempotency_key` VARCHAR(64) NOT NULL UNIQUE,
    `status` ENUM('pending', 'waiting_online', 'executed', 'failed') DEFAULT 'pending',
    `retry_count` INT UNSIGNED DEFAULT 0,
    `error_log` TEXT NULL,
    `executed_at` TIMESTAMP NULL,
    `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT `fk_delivery_order` FOREIGN KEY (`order_id`) REFERENCES `orders` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 4. Bảng lưu trữ mã PIN liên kết tài khoản tạm thời
CREATE TABLE `minecraft_link_tokens` (
    `id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `minecraft_uuid` VARCHAR(36) NOT NULL,
    `minecraft_username` VARCHAR(32) NOT NULL,
    `pin_code` VARCHAR(10) NOT NULL UNIQUE,
    `expires_at` TIMESTAMP NOT NULL,
    `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX `idx_pin_lookup` (`pin_code`, `expires_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Báo Cáo Lỗ Hổng Bảo Mật Phát Hiện & Phương Án Khắc Phục

🚨
Lỗ hổng 1: Cửa sau Test Probe trong SePay Webhook
Trong tập tin app/Services/SepayService.php, hàm xác thực webhook có đoạn kiểm tra payload nếu chứa is_test = true thì tự động bỏ qua kiểm tra chữ ký HMAC và API Key. Kẻ xấu có thể lợi dụng để gửi request giả mạo thanh toán thành công miễn phí!
Giải pháp: Xóa bỏ hoàn toàn điều kiện này hoặc bọc trong kiểm tra môi trường nghiêm ngặt if (app()->environment('local')).
⚠️
Lỗ hổng 2: Lộ Access Token Discord trên URL chuyển hướng
Trong DiscordOAuthController.php, khi hoàn tất xác thực Discord, backend chuyển hướng người dùng về frontend với Sanctum Token nằm lộ liễu trên URL query string: /auth/callback?token=1|abcdef.... Token có thể bị rò rỉ qua lịch sử trình duyệt, Proxy logs hoặc Referer header.
Giải pháp: Lưu token vào HTTP-Only Cookie hoặc Session tạm thời một lần (Flash Session).
⚠️
Lỗ hổng 3: Form liên kết tài khoản không kiểm tra quyền sở hữu
Trang hồ sơ người dùng chỉ có 1 ô nhập text username và regex ^[a-zA-Z0-9_]{3,16}$, không kiểm tra người dùng đó có thực sự sở hữu nick trong Minecraft hay không.
Giải pháp: Áp dụng ngay cơ chế OTP PIN Handshake (Module A) đã mô tả ở Phần 3.
